# Mission Reflection

Object storage is better suited for storing millions of photos than block storage because it is designed for massive amounts of unstructured data. Each photo becomes an independent object with its own metadata and unique identifier, so it can be retrieved quickly regardless of how many files exist. Block storage, on the other hand, needs a running server to manage blocks and does not scale as easily, making it impractical for a photo-sharing app with millions of users. Using Docker made deploying MinIO much easier because everything needed to run the server was packaged into one image. With a single command, I pulled the image, set environment variables, mapped the ports, and started the server in seconds. I did not have to manually install dependencies or configure the operating system, which saved time and reduced errors. A bucket, in cloud storage, is a container that holds objects. It works like a top-level folder but does not support nested directories, and each bucket has a unique name that can store unlimited objects, making it the basic unit of organization in object storage systems.

Large enterprise companies ensure their object storage data is not lost by replicating it across multiple servers and data centers. They use erasure coding, cross-region replication, regular backups, and versioning so that even if one physical server crashes, the data still exists elsewhere and can be recovered quickly. This redundancy is what makes cloud storage reliable for businesses that cannot afford downtime or data loss. My confidence in navigating the Linux command line is growing steadily. In this mission, I became more comfortable using Docker commands, checking running containers, and troubleshooting errors when the image was not available. Each lab builds on the previous one, and I feel more independent in using the terminal compared to when I started.
