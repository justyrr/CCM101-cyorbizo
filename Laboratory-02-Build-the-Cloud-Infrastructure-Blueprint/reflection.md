## 1. Which cloud infrastructure component do you think is the most important? Why?

I believe compute resources are the most critical cloud infrastructure component because they serve as the foundation for running all applications and workloads. Without processing power and memory, no application can function, regardless of how much storage or network connectivity is available. Compute resources directly impact application performance, scalability, and cost. For example, in the KillerCoda environment, the CPU cores and RAM (1 core, 1.9 GB) determined what workloads could run effectively. Additionally, compute resources are often the first consideration when architects design cloud solutions, as they define the performance baseline for the entire system. However, all components are interdependent—compute needs storage for data, networking for communication, and the OS for resource management.

## 2. How does Linux support cloud computing?

Linux supports cloud computing in several fundamental ways. First, Linux is the dominant operating system in cloud environments, powering approximately 90% of public cloud workloads. Its open-source nature allows cloud providers to customize and optimize it for their infrastructure. Second, Linux provides strong security features, user permissions, and access controls essential for multi-tenant cloud environments. Third, Linux supports containerization technologies like Docker and orchestration tools like Kubernetes, which are central to modern cloud-native architectures. Fourth, Linux's command-line interface enables powerful automation and scripting, making it ideal for infrastructure as code practices. The KillerCoda environment demonstrated this by providing a Linux system with tools like system investigation commands and Docker support.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is crucial before deployment for several critical reasons. First, it ensures all stakeholders understand the infrastructure design and requirements, enabling better collaboration and decision-making. Second, documentation serves as a single source of truth that guides the actual deployment, preventing misunderstandings and mistakes. Third, it allows team members to identify potential issues or gaps in the design before resources are committed. Fourth, documentation facilitates knowledge transfer and onboarding, helping new team members understand the system quickly. Fifth, it provides a baseline for future modifications and troubleshooting. The checklist requirements in this activity emphasized this by asking us to document our investigation findings, component analysis, and provider comparisons.
