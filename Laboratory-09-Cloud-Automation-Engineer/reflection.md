# Reflection: The Cloud Automation Engineer

In this laboratory, I learned how Bash scripts and Cron can make repetitive tasks easier to manage in a Linux environment. By creating a backup script, I discovered how multiple commands can be combined to save files into a compressed archive. I also learned how Cron can run scheduled tasks automatically, reducing the need for manual execution.

One thing I realized is that automation still requires proper planning and testing. A script may not work correctly if the file paths are incorrect or if there are errors in the commands. This is why checking the output and verifying the backup files are important before relying on an automated process.

I also understood the difference between Bash scripting and Docker Compose from our previous laboratory. Bash scripting is useful for automating commands and system tasks, while Docker Compose helps manage applications that use multiple containers. Both tools serve different purposes, but they can make system management more organized and efficient.

From Laboratories 1 to 9, I gained a better understanding of different cloud computing concepts, including infrastructure, deployment, containerization, security, monitoring, and automation. Each laboratory introduced tools and practices that helped me understand how cloud environments are managed.

Among the cloud engineering roles I explored, I found the Cloud Automation Engineer activity interesting because it allowed me to create a script that performs tasks automatically. Overall, this laboratory improved my understanding of Linux commands and scripting while teaching me that reliable automation depends on proper configuration, testing, and protecting important data.
